1. Input Data

Participant profiles include technical skills, programming languages, AI/ML skills, web development skills, database skills, UI/UX skills, soft skills, areas of interest, experience level (Beginner to Expert), previous hackathon experience, preferred team role, and project interests. Hackathon configuration includes project domain, required skills, optional skills, team size, and number of teams.

2. Feature Engineering

Raw participant data is transformed into normalized numerical features in the 0-1 range. Experience levels are mapped to 0.25, 0.50, 0.75, and 1.0. Previous hackathon experience is parsed and normalized (5+ hackathons = 1.0). Skill count is normalized against the maximum across all participants. Technical depth is computed as the ratio of advanced skills to total skills.

3. Skill Encoding

A skill vocabulary is built from all unique skills across all participants. Each participant is then encoded as a binary vector against this vocabulary (1 if they have the skill, 0 if not). This enables cosine similarity and Jaccard similarity computations between participants.

4. Team Formation Algorithm

A greedy optimization approach is used. Phase 1 anchors each team with the most experienced participants. Phase 2 iteratively assigns remaining participants to the team where they add the most value, based on a weighted score of: compatibility with existing members (35%), skill coverage gain (30%), experience balance (20%), role diversity penalty (prevents same-role clustering), and team size balance (15%). The algorithm ensures no participant appears in multiple teams.

5. Success Prediction

An explainable weighted scoring model computes 6 sub-scores, each normalized 0-100:

ComponentWeightDescription
Project-Skill Match30%Coverage of required hackathon skills
Skill Diversity20%Unique skills relative to team size
Experience15%Average experience level of members
Role Coverage15%Distinct roles covered out of 8 possible
Compatibility10%Average pairwise compatibility
Hackathon Experience10%Average prior hackathon experience

The final score is the weighted sum. The architecture is designed so a trained ML model can later replace this scoring function while keeping the same feature interface.

6. Recommendation Engine

A rule-based engine analyzes each team's composition and generates human-readable recommendations. It checks for missing critical roles (UI/UX, Frontend, Backend, AI/ML for Generative AI domain), skill coverage gaps, experience balance, hackathon experience, skill diversity, shared interests, and domain-specific needs. Output is categorized into strengths, weaknesses, and recommended improvements.
